## 为什么改

实际Mac诊断否定了“所有圈都是AA或折返”的说法：D30静止主/次路径没有负Jacobian，真实16×16面积参考也有近边压缩；按压时仅旧次路径有50个负det点。连续PSD足迹已将同模型近边采样误差相对有限面积参考降低约57%–82%，继续加全片模糊不是正确处理。

旧模型把相同输入平面按两种射程叠加，会形成没有独立环境数据支持的第二像；旧高度最大接近22pt半径，形成很厚的球透镜。中间单路径候选移除第二像但仍过厚；更浅的Rc=R+B模型又使自然图体积偏弱，均保留原图和不接收整体效果的决定。

## 当前唯一几何模型

用圆口半径R和基平面偏移B（复用现有bezel，最小1.5pt）确定球：

`Rc=sqrt(R²+B²)`，`sag=Rc-B=R²/(Rc+B)`。

深度d沿原rounded-box SDF，`t=clamp(d/R,0,1)`，实际面高由
`rise=R² t(2−t)/(sqrt(B²+R² t(2−t))+B)`得到。厚度输入保留旧的压缩比例`min(R,thickness)/R`。法线直接用同一函数导数，而不是单独调normal强度。默认R=66px/B=48px对应约11.2pt最大高度；边缘normalZ有非零几何下界B/Rc。

透射射线只走本点局部面高，沿原C1有限路径与最终位移上限；不把整片最大高度当成所有点射程。不再向第二位移像分配能量，旧environment字段仅作同位零权重的兼容输出。**不声称二维背景能提供真实外界反射。**

旧加法接触凹陷会穿透变薄的边缘，Mac负控已实际拦截。当前让请求凹陷D作用为`h_new=h²/(h+D)`；零D恒等、非负，法线按精确链式法则同步更新，不能只clamp高度却保留错误法线。

## 已经运行的检查

macOS Actions `39216943890` / commit `e54e212199ecedccd72ff2fd3d290bb29eefb501`，所有C/MSL/ObjC++实际编译仅Apple工具链。真实GPU45张同输入读回，222项独立PNG/BGRA/源输入核对；黑灰白不凭空添色、零厚度sourceidentity、shape外不变、释放精确idle、左右触点不同均通过。有限球冠数值检查包含实际高度、20%厚度压缩、解析法线对有限差分及全域按压非负。

默认132px实际映射：idle最大奇异值1.789、最小det0.600；左右按压最大奇异值约1.679、最小det约0.571，诊断点中无负det。不是任意几何/全系统的无折返定理，也不是屏幕像素证明。Mac计时只作观测，不宣称iPhone性能预算达标。

## 视觉结论

相比厚模型，多圈挤压和不必要双像减少，透射更干净；但官方参考里的完整边缘色光和整体质感尚未达标。**仅保留为进一步评审的透射几何候选，不作最终产品放行。** 正常本体/手机仍未替换；系统背景、Settings宿主、phone像素、最终视觉与全覆盖均未由本测试证明。
